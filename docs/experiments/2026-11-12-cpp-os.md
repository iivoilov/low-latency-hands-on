# C++ OS-socket compiler comparison

12 November 2026. EPYC sender → Ryzen receiver, ordinary UDP multicast over
1 Gbps. RX/L2 placement was left to the OS. GCC 14.2.0 and Clang 19.1.7 used
the installed libstdc++, separate Release builds with `-O2 -DNDEBUG` or
`-O3 -DNDEBUG`, without LTO or native-CPU flags. Existing NIC/governor settings
were retained. See [common methods and hardware](README.md).

## New-seed, four-profile pass

Four seed-43 profiles × four builds × one attempt produced **16/16 valid runs**.
Each sampled one million updates, matched the final L2 book and reported no
loss. These are single observations per build/profile pair, not three repeats.

Per-run userspace RX-to-L2 p99.9, nanoseconds:

| Profile | GCC O2 | GCC O3 | Clang O2 | Clang O3 |
| --- | ---: | ---: | ---: | ---: |
| P1 | 670 | 620 | 570 | 580 |
| P2 | 1250 | 670 | 1160 | 560 |
| P3 | 680 | 1310 | 1100 | 920 |
| P4 | 1070 | 670 | 580 | 1120 |

There is no consistent O3 advantage across these observations. Unpinned CPU
placement and scheduler activity were not controlled here, so compiler rankings
cannot be generalized. The later [affinity study](2026-11-12-cpu-affinity.md)
addresses that source of variability.

## Earlier controls and retained failure

The initial P1 seed-42, 100k-update comparison had 12/12 valid attempts.
The million-update P1 seed-42 comparison had 11/12 valid attempts, with three
planned attempts per build. A Clang O3 trial stopped after 242,816 samples
when sequence 243332 arrived while 243004 was expected: **328 messages missing**,
range 243004–243331. The separate gap queue retained the range. Socket and ring
drop counters were zero, so the loss origin remains unknown. It was not retried
or included in valid-run percentiles.

The earlier aggregate tables and the failure record are included in
[JSON](2026-11-12-cpp-os-results.json), together with all 16 seed-43 numerical
trial records, payload rates, schedule slip, workload and binary hashes.
Reproduction: [build variants and remote runner](../../benchmark/README.md).
